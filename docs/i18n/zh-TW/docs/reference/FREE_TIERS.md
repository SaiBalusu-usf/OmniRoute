## TL;DR — OmniRoute 實際彙總了多少免費推論額度？

| 指標                                 | Tokens／月 | 意義                                                                                                                                                                                                                                                                     |
| ------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **有明文記載的週期性額度（穩定）**   | **~1.47B** | 免費方案**資源池**（依模型目錄計算），每個共用資源池只計算**一次**。這是 `/api/free-tier/summary` 與儀表板「免費方案預算」頁面的即時資料來源。**請使用此數字。**                                                                                                         |
| **+ 首月註冊贈額**                   | **~2.07B** | 穩定額度 + 一次性註冊贈額（Z.AI 20M、DeepSeek 5M，……），依帳戶去重。**僅限第一個月** — 不會再次發放。                                                                                                                                                                    |
| **+ 永久免費，無公開上限**           | _無法量化_ | `siliconflow`、`glm-cn`（GLM-4-Flash）、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud` — 確實提供週期性存取，但受速率／並行限制，且**沒有可供計算的 token 上限**。會列出，但永不納入總和（以 `RPM×24/7` 計算正是我們拒絕採用的灌水方式）。 |
| **+ 儲值解鎖加成**                   | **+~24M**  | 一次性儲值 **$10** 至 OpenRouter，可將其免費資源池從每日 50 次請求提高至 1000 次。此數字會單獨列示，因此絕不會灌大穩定額度。                                                                                                                                             |
| **+ 需通過地區身分驗證**             | **+~6M**   | `modelscope`（綁定 Alibaba Cloud + 中國大陸實名認證）。這是確實存在的週期性配額，會以 `gatedRecurringTokens`／`gatedProviders` 呈現，並顯示於儀表板中。絕不納入標題數字：通過地區身分驗證後可額外取得約 6M。                                                             |
| 理論上限（所有速率限制，全天候使用） | ~10B       | 將所有提供者的速率限制按不間斷使用外推後的總和。**並非保證值** — 請勿將此數字用作標題。                                                                                                                                                                                  |

**如實呈現的標題：** _OmniRoute 彙總了跨 34 個免費方案資源池、每月約 **~1.47B 有明文記載的免費 tokens**（計入註冊贈額後，首月最高約 ~2.07B），另有大量永久免費且無上限的提供者 — 再搭配 RTK + Caveman 壓縮（可節省 15–95% token），還能進一步延長可用額度。_

> **為何此數字從先前的 ~1.94B 降低。** 2026-06-17 的更新是誠實性修正，而非額度損失：`gemini` 現已依資源池去重（先前分別計算每個 Flash 變體而造成灌水，462M → 60M）；`cloudflare-ai` 已修正為其實際的每日 10k Neurons（122M → 30M）；`doubao` 已重新分類為一次性註冊贈額（而非週期性額度）；並移除已終止的方案（`chutes`／`phind`／`kluster` 已停止提供）。部分減幅由 `llm7`（修正為每日 5M → 150M）及新的免費提供者（Kilo、OpenCode Zen、Z.AI GLM-Flash）抵銷。
>
> **在 v3.8.42 中進一步修正為 ~1.37B：** `longcat` 的免費預覽結束後，已從每月 150M 的週期性額度重新分類為一次性 10M 註冊贈額。仍採用相同的誠實原則 — 沒有任何提供者因疏失而遭到移除。
>
> **Felo Web 退役後於 2026-08-26 更新：** 在其 GPL 衍生來源／授權狀態仍為 HOLD 期間，Felo Web 不納入計算；當時來源回報了 38 個資源池鍵。資源池數量是即時的，並受 CI 閘門控管（若上述數字與 `computeFreeModelTotals()` 不一致，`check:docs-counts` 將使建置失敗）。
>
> **已於 2026-09-02 依照提供者自有頁面重新稽核**（來源：`open-sse/config/freeModelCatalog.data.ts` 中每個重新稽核項目旁的 `// evidence:` 註解）：`gemini` 與 `ollama-cloud` 已不再公布 token 數字（Google 於 2025-12-23 移除了各模型的免費方案表格；Ollama 的 Free 方案僅標示為「入門使用額度」），現改列為**無上限**且永不納入總和（−80M）；`groq` 是五個**各模型獨立**的每日 200K token 上限（每個 6M，+15M），並移除三個已退役的 ID；`nara` 是單一每日 7M 的額度池（+60M，210M）。`mistral` 的 1B 僅能在帳戶主控台中看到 — 請參閱「方法」下的_證據類別_。當時來源回報了 35 個此類鍵（−3：`gemini` 與 `ollama-cloud` 移至無上限清單，而 Groq 的各模型上限並非共用資源池）。
>
> **於 2026-09-03 修正為 ~1.47B（#11773）：** `cerebras` 已從每月 30M 的週期性額度（舊版免信用卡、每日 1M tokens 的試用方案）重新分類為需要付款方式的一次性 $5 註冊贈額。採用與 LongCat 相同的誠實原則。來源目前回報 34 個週期性資源池鍵，以及約 ~1.47B 的穩定額度。

最大的**有文件依據**貢獻者：`mistral` 1.00B、`nara` 210M、`llm7` 150M、`groq` 30M（五個各模型上限）、`cloudflare-ai` 30M、`api-airforce` 24M。（`longcat` 不計入——其 10M LongCat-2.0 額度是一次性、須通過 KYC 的註冊贈額，而非每月定期預算。）

> ⚠️ 理論上限（約 10B）因僅設有速率限制、**未公布 token 上限**的提供者（`tencent`、`siliconflow`、`nvidia`、`baidu`、`glm-cn`、`sparkdesk`）而被放大；其數值是以 `RPM/TPM × 24/7 × 30d` 計算——這是任何單一帳戶都無法持續達到的理論最大值。因此，它們**不計入**可合理佐證的數字（而是列於「永久免費、無上限」一列）。這種灌水方式也正是競爭對手所宣稱的數十億額度並不可靠的原因。

## 兩種機制 — 計算與判定

OmniRoute 透過兩種機制回答「是否免費？」；這兩種機制刻意讀取
不同的來源：

| 機制           | 真實來源                                                                                                                                                 | 適用介面                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **計算／顯示** | 已解析的目錄 — 以 Radar 摘要資訊（`getRadarCatalog`）覆蓋已發布的基準資料                                                                                | 免費方案總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅限已發布的目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），以及本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用者：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要摘要資訊可用，計算結果便可隨時改進。判定則維持以
發布成品為準，因此瀏覽器與伺服器上的答案完全一致、
可離線重現，且無須資料庫即可測試。若讓瀏覽器
預覽讀取一個來源，而伺服器匯入讀取另一個來源，就會導致
預覽結果與點擊後實際發生的情況不一致 — 因此刻意保留
這項區分。

## 方法論與注意事項

- 數字是根據各提供者截至 **2026-06-17** 所記載之免費方案限制，透過網路研究整理出的**上限估計值**。免費方案經常變動——在依賴任何數字之前，請重新驗證。
- **每筆項目實際保證的內容。** 各筆項目都沒有逐列的可信度評等，API 也不提供此資訊——請將上述每個數字都視為品質相同但未明示的估計值。不過，有兩項資訊不同，因為它們是人工整理，而非推論得出：5 筆項目具有獨立記載的強制停止機制，13 筆項目具有提示詞訓練揭露。只有在提供者自己的條款明確指出，超出免費額度後會拒絕要求，而不是在未提示的情況下開始計費時，才會設定 `hardStopGuaranteed`，且來源會列在該項目旁的註解中；此值絕不會預設為 `true`，尚未經任何人驗證的項目會維持未設定狀態。因此，缺少強制停止旗標表示「尚未確立」，而不是「已知會向你收費」。**STRICT 模式**（選擇啟用的 `freeAccessPolicy=strict` 路由防護）只信任具有此旗標的項目；其他所有免費方案都會以 `no-hard-stop` 為由排除（請參閱 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。
- `estMonthlyFreeTokens` = 僅計入每月週期性提供的 token。**一次性的註冊點數不會重複提供**，因此計為 0。已停止的方案也計為 0。
- 每日 token 上限 → `monthly = daily × 30`。若只記載 RPD → `RPD × ~800 output tokens × 30`。若只有 RPM/TPM（無每日上限）→ **無上限**（見下文）。
- **永久免費，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：這些確實是持續提供的免費存取，但受到速率／並行數限制。我們將其分類為 `recurring-uncapped`，且**絕不加總**——以 `RPM × 24/7 × 30d` 計算會產生不切實際的上限（也就是我們拒絕採用的灌水算法）。列出它們是為了讓你知道這些方案確實存在。
- **儲值解鎖加成：** 一次性的小額儲值，可永久提高免費配額（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。此數字會分開列示，不納入穩定配額的主要數字。
- **資格限制配額**（`eligibilityGate: "regional-identity"`）：確實存在的週期性配額，但只有在完成受地區限制的身分驗證後才會開放（目前為中國大陸實名驗證）。依照相同的配額池去重規則，計入獨立數字（`gatedRecurringTokens`），絕不納入穩定配額的主要數字。其制度類型（`freeType`）維持不變，因此路由行為也不變。
- **證據類別。** 規則如下：目錄中的數字會在該項目旁的 `// evidence:` 註解中引用其來源——`public-page`（任何人皆可閱讀的提供者頁面）、`api-public`（提供者無須驗證即可存取的端點，例如 NaraRouter 位於 router.bynara.id 的公開方案端點），或 `console-verified <date> por <who>`（該數字只能在帳戶控制台內看到；註解會記錄查看者及查看日期，以及說明該上限確實存在的公開頁面）。目前狀態如下：於 2026-09-02 重新稽核的五個區塊都帶有此資訊（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早於 2026-09-02 重新稽核的項目，在被修改前會沿用先前的研究結果；任何**新增或變更**但沒有證據註解的數字都屬於錯誤。目前只有 `mistral` 經控制台驗證。

## 為什麼我們的數字比其他彙整服務小

這個領域中大多數的「每月免費 token」數字，都是將各模型標示的額度加總而成。我們刻意不這麼做：

- **每個共用額度池只計算一次。** Mistral 的免費方案是每個組織每月共用 1B 的額度；將它列在五個模型下並不會讓它變成 5B。若依模型加總，我們自己的目錄會顯示為 **~7.4B**（於 2026-09-03 重新計算；此數字不受 CI 檢查約束——每當目錄變更時都應重新測量）——標題寫的是 **~1.47B**，因為這才是每個提供者各一個帳戶實際可使用的額度。
- **每日上限會換算，速率限制則不會。** 有明確文件記載的 tokens/day 上限會換算成 `× 30`；有明確文件記載的 requests/day 上限會換算成 `RPD × ~800 tokens × 30`；若提供者只公布每分鐘請求數，則**不會**提供每月數字，而是列為_無上限_，且絕不納入加總。將速率限制乘以 24/7 正是我們拒絕採用的灌水方式。
- **需要區域身分驗證才能取得的額度會分開顯示**（`+~6M behind regional identity verification`），因為大多數讀者無法使用這些額度。
- **註冊點數僅適用於首月**，並會作為第二個數字單獨呈現，絕不混入穩定的常態數字中。
- **此數字由 CI 強制驗證。** `npm run check:docs-counts` 會根據目錄重新計算總額，並在此檔案、README 或預算卡片中的數字與計算結果不一致時，讓建置失敗。

## 詞彙表

| 術語                 | 含義                                                   |
| -------------------- | ------------------------------------------------------ |
| **RPM / RPD / RPH**  | 每分鐘／每日／每小時的請求數                           |
| **TPM / TPD**        | 每分鐘／每日的權杖數                                   |
| **有明文記載的額度** | 提供者公布明確的每日／每月權杖上限（可據以規劃的預算） |
| **理論上限**         | `rate-limit × 24/7 × 30d` — 最大值，而非已授予的預算   |
| **Neuron**           | Cloudflare 運算單位（約等於 1 個輸出權杖）             |
