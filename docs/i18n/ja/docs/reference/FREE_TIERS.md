## 2 つの運用方式 — 集計と判定

OmniRoute は「無料か？」という問いに対し、意図的に異なるソースを参照する 2 つの運用方式で回答します：

| 運用方式        | 信頼できる情報源                                                                                                                                                                 | 適用箇所                                                                                                                                       |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **集計 / 表示** | 解決済みカタログ — 配布時のベースラインに Radar フィード（`getRadarCatalog`）を重ね合わせたもの                                                                                  | 無料枠の合計、予算カード、ダッシュボード                                                                                                       |
| **判定**        | 配布済みカタログのみ（`open-sse/config/freeModelCatalog.data.ts` 内の `FREE_MODEL_BUDGETS`）とローカルヒューリスティクス（`:free` サフィックス、料金がゼロ、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` を使用するすべての箇所：モデルのインポート、`auto/*` ルーティング、`GET /v1/models`、およびブラウザプレビュー |

フィードが利用可能であれば、集計は随時改善できます。一方、判定はリリース成果物に固定されるため、ブラウザとサーバーで回答が一致し、オフラインでも再現可能で、データベースなしでもテストできます。ブラウザプレビューとサーバー側のインポートが異なるソースを参照すると、プレビュー内容とクリック時の実際の動作が一致しなくなるため、この分離は意図的に維持されています。

## 方法論と注意事項

- 数値は、Web 調査により収集した、**2026-06-17** 時点で各プロバイダーが文書化している無料枠上限に基づく**上限推定値**です。無料枠は頻繁に変更されるため、数値を利用する前に再確認してください。
- **各エントリが実際に保証している内容。** エントリごとの信頼度評価はなく、API からも提供されません。上記のすべての数値は、明記されていない同一水準の品質に基づく推定値として扱ってください。ただし、推論ではなく手作業で精査されているため、次の 2 つの情報は異なります。5 件のエントリには、独立して文書化された確実な停止条件があり、13 件のエントリには、プロンプトのトレーニング利用に関する開示があります。`hardStopGuaranteed` は、無料割当量を超過した場合に、通知なしで課金を開始するのではなくリクエストを拒否するとプロバイダー自身の規約に明記されている場合にのみ設定され、その出典はエントリの隣のコメントに記載されます。デフォルトで `true` に設定されることはなく、誰も検証していないエントリでは未設定のままです。したがって、確実な停止を示すフラグがないことは、「課金されると判明している」という意味ではなく、「確認されていない」という意味です。**STRICT モード**（オプトインの `freeAccessPolicy=strict` ルーティングガード）は、このフラグが設定されたエントリのみを信頼します。それ以外の無料枠はすべて `no-hard-stop` として除外されます（`open-sse/services/autoCombo/strictZeroCostFilter.ts` を参照）。
- `estMonthlyFreeTokens` = 毎月繰り返し付与されるトークンのみ。**初回登録時に一度だけ付与されるクレジットは繰り返し付与されない**ため、0 として数えます。廃止された枠も 0 です。
- 1 日あたりのトークン上限 → `monthly = daily × 30`。RPD のみが文書化されている場合 → `RPD × 約800出力トークン × 30`。RPM/TPM のみで 1 日あたりの上限がない場合 → **上限なし**（以下を参照）。
- **恒久的に無料だが、公開されたトークン上限がないもの**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：これらは実際に繰り返し利用できる無料アクセスであり、レートまたは同時実行数による制限があります。これらは `recurring-uncapped` に分類し、**合計には決して含めません**。`RPM × 24/7 × 30d` を計算すると非現実的な上限値になるためです（そのような水増しは採用しません）。利用可能な選択肢であることが分かるよう、一覧には掲載しています。
- **入金による上限引き上げ：** 1 回限りの少額入金により、無料割当量が恒久的に引き上げられる仕組みです（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。通常時の主要数値には含めず、別の数値として報告します。
- **利用資格によって制限される割当量**（`eligibilityGate: "regional-identity"`）：地域に紐づく本人確認（現時点では中国本土の実名認証）を完了した後にのみ利用可能になる、実際に繰り返し付与される割当量です。同一プールの重複排除ルールを適用して別の数値（`gatedRecurringTokens`）に算入し、通常時の主要数値には決して含めません。区分（`freeType`）は変更されないため、ルーティングも変更されません。
- **エビデンスの分類。** ルール：カタログ内の数値は、そのエントリの隣にある `// evidence:` コメントで出典を示します。分類は、`public-page`（誰でも閲覧できるプロバイダーのページ）、`api-public`（プロバイダーの未認証エンドポイント。例：router.bynara.id にある NaraRouter の公開プランエンドポイント）、または `console-verified <date> por <who>`（数値がアカウントコンソール内でのみ確認可能であり、そのコメントには、誰がいつ確認したか、および上限が存在することを示す公開ページが記録されます）です。現時点では、2026-09-02 に再監査された 5 つのブロック（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）にこの情報があります。2026-09-02 の再監査より前から存在するエントリは、更新されるまで以前の調査内容を引き継ぎます。エビデンスコメントのない**新規または変更済み**の数値はバグです。現時点でコンソール検証済みなのは `mistral` のみです。

## 当社の数値が他のアグリゲーターより小さい理由

この分野で見られる「1か月あたりの無料トークン」の数値の大半は、モデルごとの表示値を合計したものです。当社では意図的にそうしていません：

- **各共有プールは1回だけ数えます。** Mistral の無料プランは、組織ごとに月間 1B の割り当てが1つです。5つのモデルに分けて掲載しても 5B にはなりません。モデルごとに合計すると、当社自身のカタログは **~7.4B** になります（2026-09-03 に再計算。この数値は CI で検証されていないため、カタログが変更されるたびに再測定してください）が、見出しでは **~1.47B** としています。これは、各プロバイダーのアカウントを1つずつ持つ場合に実際に利用できる量だからです。
- **日次上限は換算しますが、レート制限は換算しません。** 文書化された tokens/day の上限は `× 30`、文書化された requests/day の上限は `RPD × ~800 tokens × 30` として換算します。requests-per-minute のみを公開しているプロバイダーには月間数値を設定せず、_上限なし_ として掲載し、合計には決して含めません。レート制限を 24/7 で掛け合わせるような水増しは行いません。
- **地域別の本人確認が必要なクォータは別に表示します**（`+~6M behind regional identity verification`）。ほとんどの読者は利用できないためです。
- **サインアップクレジットは初月限定**であり、通常時の数値には混ぜず、2つ目の数値として報告します。
- **この数値は CI によって強制的に検証されます。** `npm run check:docs-counts` はカタログから合計を再計算し、このファイル、README、または予算カードの数値と一致しなくなった場合にビルドを失敗させます。

## 用語集

| 用語                   | 意味                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| **RPM / RPD / RPH**    | 1分あたり / 1日あたり / 1時間あたりのリクエスト数                                                      |
| **TPM / TPD**          | 1分あたり / 1日あたりのトークン数                                                                      |
| **文書化された付与量** | プロバイダーが明示的な1日または1か月あたりのトークン上限を公開しているもの（根拠として提示可能な予算） |
| **理論上の上限**       | `rate-limit × 24/7 × 30d` — 付与された予算ではなく、最大値                                             |
| **Neuron**             | Cloudflareのコンピューティング単位（出力トークン約1個分）                                              |

> 2026-06-05時点のプロバイダー別調査から生成されています。更新するには、調査ワークフロー（`_tasks/features-v3.8.12`を参照）を再実行してください。
