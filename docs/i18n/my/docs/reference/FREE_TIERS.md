> **အသုံးပြုသူများအတွက်**: ရိုးရှင်းသော လမ်းညွှန်ကို ရှာနေပါသလား။ အခမဲ့ AI ရယူရန် အဆင့်ဆင့်ညွှန်ကြားချက်များအတွက် [အခမဲ့အဆင့်များ လမ်းညွှန်](../getting-started/FREE-TIERS-GUIDE.md) ကို ကြည့်ပါ။

> **နောက်ဆုံး သုတေသနပြုထားသည့်ရက်:** 2026-06-17 — အခမဲ့အဆင့် quota နှင့် ToS တိုင်းကို အသစ်ပြန်လည်စစ်ဆေးထားသော ဝန်ဆောင်မှုပေးသူတစ်ဦးချင်းစီအလိုက် ဝဘ်သုတေသန (တရားဝင်စာရွက်စာတမ်းများ + နောက်ဆုံး 7 ရက်အတွင်း သတင်းများ၊ ဆန့်ကျင်ဘက်အမြင်ဖြင့် အတည်ပြုစစ်ဆေးသည့် agent 50 ခုပါ pass)။ **2026-09-02 တွင် တစ်စိတ်တစ်ပိုင်း ပြန်လည်စစ်ဆေးခဲ့သည်** (`gemini`, `ollama-cloud`, `groq`, `nara`, `mistral` — အောက်ရှိ ရက်စွဲပါမှတ်ချက်ကို ကြည့်ပါ)။
> **အမှန်တရား၏ မူရင်းရင်းမြစ် (catalog):** `open-sse/config/freeModelCatalog.ts` (MODEL တစ်ခုချင်းစီအလိုက် budget များ၊ pool ထပ်နေမှုများကို ဖယ်ရှားထားသည်)။ အောက်ပါ token-budget ကိန်းဂဏန်းများသည် လက်ရှိ ဝဘ်သုတေသနမှ ရရှိထားပြီး **ခန့်မှန်းချက်** တစ်ခုသာဖြစ်သည် — [နည်းလမ်းနှင့် သတိပြုရန်အချက်များ](#methodology--caveats) ကို ကြည့်ပါ။

## TL;DR — OmniRoute က အခမဲ့ inference ဘယ်လောက်ကို အမှန်တကယ် စုစည်းပေးသလဲ။

| **မှတ်တမ်းတင်ထားသော ပုံမှန်ပြန်လည်ရရှိသည့် grant (တည်ငြိမ်ပမာဏ)**   | **~1.47B**        | အခမဲ့အဆင့် **pool များ** (model တစ်ခုချင်းစီအလိုက် catalog) ဖြစ်ပြီး မျှဝေအသုံးပြုသော pool တစ်ခုစီကို **တစ်ကြိမ်သာ** ရေတွက်ထားသည်။ `/api/free-tier/summary` နှင့် dashboard ရှိ Free-Tier Budget စာမျက်နှာ၏ လက်ရှိဒေတာရင်းမြစ်ဖြစ်သည်။ **ဤကိန်းဂဏန်းကို အသုံးပြုပါ။**                                                                                                                               |
| **+ စာရင်းသွင်းခရက်ဒစ်များပါဝင်သည့် ပထမလ**                          | **~2.07B**        | တည်ငြိမ်ပမာဏ + တစ်ကြိမ်သာရရှိသည့် စာရင်းသွင်းခရက်ဒစ်များ (Z.AI 20M၊ DeepSeek 5M၊ …) ဖြစ်ပြီး account တစ်ခုချင်းစီအလိုက် ထပ်နေမှုများကို ဖယ်ရှားထားသည်။ **ပထမလအတွက်သာ** — ထပ်မံမရရှိပါ။                                                                                                                                                                                                              |

| **+ ဒေသဆိုင်ရာ အထောက်အထားစစ်ဆေးမှုနောက်ကွယ်ရှိ ပမာဏ**               | **+~6M**          | `modelscope` (Alibaba Cloud ချိတ်ဆက်မှု + တရုတ်ပြည်မကြီး၏ အမည်ရင်းအတည်ပြုခြင်း)။ အမှန်တကယ် ပုံမှန်ပြန်လည်ရရှိသော quota ဖြစ်ပြီး `gatedRecurringTokens` / `gatedProviders` အဖြစ်နှင့် dashboard ပေါ်တွင် ဖော်ပြထားသည်။ အဓိကကိန်းဂဏန်းထဲ ဘယ်တော့မျှ မပေါင်းပါ: ဒေသဆိုင်ရာ အထောက်အထားအတည်ပြုမှုနောက်ကွယ်တွင် +~6M ရှိသည်။                                                                              |

**ရိုးသားသော အဓိကဖော်ပြချက်:** _OmniRoute သည် အခမဲ့အဆင့် pool 34 ခုမှတစ်ဆင့် **တစ်လလျှင် မှတ်တမ်းတင်ထားသော အခမဲ့ token ~1.47B** ကို စုစည်းပေးသည် (စာရင်းသွင်းခရက်ဒစ်များနှင့်အတူ ပထမလတွင် ~2.07B အထိ) — ထို့အပြင် အမြဲတမ်းအခမဲ့ဖြစ်ပြီး ကန့်သတ်ချက်မရှိသော ဝန်ဆောင်မှုပေးသူများစွာလည်း ရှိသည် — RTK + Caveman compression (token 15–95% ချွေတာမှု) က ယင်းပမာဏကို ပိုမိုကြာရှည်အသုံးခံစေသည်။_

> **ယခင် ~1.94B မှ အဘယ်ကြောင့် လျော့ကျသွားသနည်း။** 2026-06-17 ပြန်လည်စစ်ဆေးမှုသည် အမှန်တကယ်ဆုံးရှုံးမှုမဟုတ်ဘဲ ရိုးသားမှုအတွက် ပြင်ဆင်ချက်ဖြစ်သည်။ `gemini` ကို ယခု pool ထပ်နေမှုဖယ်ရှား၍ ရေတွက်ထားသည် (ယခင်က Flash variant တစ်ခုစီကို သီးခြားရေတွက်ထားသဖြင့် 462M → 60M အထိ ဖောင်းပွခဲ့သည်)၊ `cloudflare-ai` ကို ၎င်း၏ အမှန်တကယ် တစ်ရက်လျှင် 10k-Neurons ပမာဏအတိုင်း ပြင်ဆင်ခဲ့သည် (122M → 30M)၊ `doubao` ကို ပုံမှန်ပြန်လည်ရရှိသည့်ပမာဏမဟုတ်ဘဲ တစ်ကြိမ်သာရရှိသည့် စာရင်းသွင်းခရက်ဒစ်အဖြစ် ပြန်လည်အမျိုးအစားသတ်မှတ်ခဲ့ပြီး ပိတ်သိမ်းသွားသော အဆင့်များ (`chutes`/`phind`/`kluster` ရပ်ဆိုင်းထားသည်) ကို ဖယ်ရှားခဲ့သည်။ ယင်းလျော့ကျမှုကို `llm7` (မှန်ကန်သော တစ်ရက်လျှင် 5M → 150M) နှင့် အခမဲ့ဝန်ဆောင်မှုပေးသူအသစ်များ (Kilo, OpenCode Zen, Z.AI GLM-Flash) က တစ်စိတ်တစ်ပိုင်း ပြန်ဖြည့်ပေးထားသည်။

## နည်းစနစ်နှင့် သတိပြုရန်အချက်များ

- ကိန်းဂဏန်းများသည် ဝဘ်သုတေသနမှ စုဆောင်းထားပြီး **2026-06-17** ရက်နေ့အထိ ဝန်ဆောင်မှုပေးသူတစ်ဦးချင်းစီ၏ မှတ်တမ်းတင်ထားသော အခမဲ့အဆင့် ကန့်သတ်ချက်များမှ ရရှိသည့် **အများဆုံးဖြစ်နိုင်ခြေ ခန့်မှန်းချက်များ** ဖြစ်သည်။ အခမဲ့အဆင့်များသည် အဆက်မပြတ် ပြောင်းလဲနေသောကြောင့် ကိန်းဂဏန်းတစ်ခုကို အားကိုးအသုံးမပြုမီ ပြန်လည်အတည်ပြုပါ။
- **အချက်အလက်တစ်ခုက အမှန်တကယ် အာမခံသည့်အရာ။** အချက်အလက်တစ်ခုချင်းစီတွင် ယုံကြည်စိတ်ချရမှု အဆင့်သတ်မှတ်ချက် မပါရှိသကဲ့သို့ API ကလည်း ယင်းကို မပေးပါ — ထို့ကြောင့် အထက်ပါကိန်းဂဏန်းတိုင်းကို ဖော်ပြမထားသော တူညီသည့် အရည်အသွေးအဆင့်ရှိ ခန့်မှန်းချက်အဖြစ် သဘောထားပါ။ သို့သော် အချက်နှစ်ချက်မှာ ခန့်မှန်းထားခြင်းမဟုတ်ဘဲ လူကိုယ်တိုင် စိစစ်ထည့်သွင်းထားသောကြောင့် ကွဲပြားသည်- အချက်အလက် 5 ခုတွင် သီးခြားမှတ်တမ်းတင်ထားသော အတိအကျရပ်တန့်မှု ပါရှိပြီး အချက်အလက် 13 ခုတွင် prompt-training ဆိုင်ရာ ထုတ်ဖော်ချက် ပါရှိသည်။ အခမဲ့ခွင့်ပြုပမာဏကို ကျော်လွန်သွားပါက သင့်ကို တိတ်တဆိတ် စတင်ငွေကောက်ခံခြင်းမပြုဘဲ တောင်းဆိုမှုကို ငြင်းပယ်မည်ဟု ဝန်ဆောင်မှုပေးသူ၏ ကိုယ်ပိုင်စည်းကမ်းချက်များတွင် ဖော်ပြထားမှသာ `hardStopGuaranteed` ကို သတ်မှတ်ပြီး၊ ရင်းမြစ်ကို သက်ဆိုင်ရာအချက်ဘေးရှိ မှတ်ချက်တွင် ထည့်သွင်းထားသည်။ ၎င်းကို မည်သည့်အခါမျှ ပုံသေ `true` အဖြစ် မသတ်မှတ်ဘဲ၊ မည်သူမျှ အတည်မပြုရသေးသော အချက်ကို သတ်မှတ်မထားဘဲ ထားသည်။ ထို့ကြောင့် hard-stop အမှတ်အသား မရှိခြင်းသည် "အတည်မပြုရသေး" ဟု ဆိုလိုပြီး "သင့်ကို ငွေကောက်ခံမည်ဟု သိထားသည်" ဟု မဆိုလိုပါ။ **STRICT mode** (ရွေးချယ်အသုံးပြုရသော `freeAccessPolicy=strict` routing guard) သည် အဆိုပါအမှတ်အသား ပါရှိသည့် အချက်များကိုသာ ယုံကြည်သည်။ အခြားအခမဲ့အဆင့်အားလုံးကို `no-hard-stop` အဖြစ် ဖယ်ထုတ်သည် (`open-sse/services/autoCombo/strictZeroCostFilter.ts` ကို ကြည့်ပါ)။
- `estMonthlyFreeTokens` = လစဉ် ထပ်တလဲလဲရရှိသော token များသာ။ **တစ်ကြိမ်တည်းရရှိသော အကောင့်ဖွင့် credit များသည် ထပ်မံမရရှိပါ**၊ ထို့ကြောင့် 0 အဖြစ် ရေတွက်သည်။ ရပ်ဆိုင်းပြီးသော အဆင့်များကိုလည်း 0 အဖြစ် ရေတွက်သည်။
- နေ့စဉ် token ကန့်သတ်ချက် → `monthly = daily × 30`။ RPD ကိုသာ မှတ်တမ်းတင်ထားပါက → `RPD × ~800 output tokens × 30`။ RPM/TPM သာရှိပြီး နေ့စဉ်ကန့်သတ်ချက် မရှိပါက → **အကန့်အသတ်မရှိ** (အောက်တွင် ကြည့်ပါ)။
- **အမြဲတမ်းအခမဲ့ဖြစ်သော်လည်း ထုတ်ပြန်ထားသော token ကန့်သတ်ချက်မရှိသည့် ဝန်ဆောင်မှုများ** (`siliconflow`, `glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`): ဤဝန်ဆောင်မှုများသည် အမှန်တကယ် ထပ်တလဲလဲရရှိနိုင်သော အခမဲ့အသုံးပြုခွင့်များဖြစ်ပြီး rate/concurrency ကန့်သတ်ချက်များ ရှိသည်။ ၎င်းတို့ကို `recurring-uncapped` အဖြစ် ခွဲခြားပြီး **မည်သည့်အခါမျှ ပေါင်းမတွက်ပါ** — `RPM × 24/7 × 30d` ဟု မြှောက်ခြင်းသည် လက်တွေ့မကျသော အမြင့်ဆုံးပမာဏကို ဖြစ်ပေါ်စေမည်ဖြစ်ပြီး ထိုသို့ ဖောင်းပွတွက်ချက်ခြင်းကို ကျွန်ုပ်တို့ လက်မခံပါ။ ၎င်းတို့ရှိကြောင်း သိနိုင်စေရန် စာရင်းတွင် ထည့်သွင်းထားသည်။
- **Deposit-unlock တိုးမြှင့်မှု:** တစ်ကြိမ်သာ အနည်းငယ် ငွေဖြည့်ခြင်းဖြင့် အခမဲ့ quota ကို အမြဲတမ်း တိုးမြှင့်ပေးခြင်း (OpenRouter: $10 → 1000 req/day ≈ +24M/mo)။ သီးခြားကိန်းဂဏန်းအဖြစ် ဖော်ပြပြီး ပုံမှန်တည်ငြိမ်သော အဓိကကိန်းဂဏန်းထဲတွင် မထည့်သွင်းပါ။
- **အရည်အချင်းပြည့်မီမှုအပေါ် မူတည်သော quota များ** (`eligibilityGate: "regional-identity"`): ဒေသအလိုက် သတ်မှတ်ထားသော အထောက်အထား စိစစ်မှု (လက်ရှိတွင် တရုတ်ပြည်မကြီး၏ အမည်ရင်းဖြင့် အတည်ပြုခြင်း) ပြီးမြောက်မှသာ ဖွင့်ပေးသည့် အမှန်တကယ် ထပ်တလဲလဲရရှိသော quota ဖြစ်သည်။ တူညီသော pool-dedupe စည်းမျဉ်းဖြင့် သီးခြားကိန်းဂဏန်း (`gatedRecurringTokens`) ထဲသို့ ရေတွက်ပြီး ပုံမှန်တည်ငြိမ်သော အဓိကကိန်းဂဏန်းထဲသို့ မည်သည့်အခါမျှ မထည့်သွင်းပါ။ စနစ်အမျိုးအစား (`freeType`) သည် မပြောင်းလဲသောကြောင့် routing လည်း မပြောင်းလဲပါ။
- **အထောက်အထား အမျိုးအစားများ။** စည်းမျဉ်းမှာ- catalog ထဲရှိ ကိန်းဂဏန်းတစ်ခုသည် သက်ဆိုင်ရာအချက်ဘေးရှိ `// evidence:` မှတ်ချက်တွင် ၎င်း၏ရင်းမြစ်ကို ကိုးကားရမည် — `public-page` (မည်သူမဆို ဖတ်ရှုနိုင်သော ဝန်ဆောင်မှုပေးသူ၏ စာမျက်နှာ)၊ `api-public` (ဝန်ဆောင်မှုပေးသူ၏ အထောက်အထားစစ်ဆေးရန်မလိုသော endpoint၊ ဥပမာ router.bynara.id ရှိ NaraRouter ၏ အများသုံး plans endpoint) သို့မဟုတ် `console-verified <date> por <who>` (ကိန်းဂဏန်းကို အကောင့် console အတွင်း၌သာ မြင်နိုင်သည်။ မှတ်ချက်တွင် မည်သူက မည်သည့်အချိန်၌ မြင်ခဲ့ကြောင်းနှင့် ကန့်သတ်ချက်ရှိကြောင်း ဖော်ပြထားသော အများသုံးစာမျက်နှာကို မှတ်တမ်းတင်ထားသည်) ဖြစ်သည်။ လက်ရှိအခြေအနေမှာ- 2026-09-02 တွင် ပြန်လည်စစ်ဆေးခဲ့သော block ငါးခုတွင် ၎င်းပါရှိသည် (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`)။ 2026-09-02 ပြန်လည်စစ်ဆေးမှုမတိုင်မီရှိပြီးသား အချက်များသည် ပြင်ဆင်မွမ်းမံချိန်မရောက်မချင်း အစောပိုင်းသုတေသနကို ဆက်လက်အမွေဆက်ခံသည်။ အထောက်အထားမှတ်ချက်မပါသော **အသစ် သို့မဟုတ် ပြောင်းလဲထားသည့်** ကိန်းဂဏန်းမှန်သမျှသည် bug တစ်ခုဖြစ်သည်။ လက်ရှိတွင် `mistral` တစ်ခုတည်းသာ console-verified ဖြစ်သည်။

## ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းသည် အခြား aggregator များ၏ ကိန်းဂဏန်းများထက် အဘယ်ကြောင့် ပိုနည်းသနည်း

ဤနယ်ပယ်ရှိ "တစ်လလျှင် အခမဲ့ token" ကိန်းဂဏန်းအများစုသည် model တစ်ခုချင်းစီအလိုက် ဖော်ပြထားသော ပမာဏများကို ပေါင်းထားခြင်းဖြစ်သည်။ ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းမှာ ရည်ရွယ်ချက်ရှိရှိ ထိုသို့မဟုတ်ပါ-

- **မျှဝေသုံးစွဲရသော pool တစ်ခုစီကို တစ်ကြိမ်သာ ရေတွက်ပါသည်။** Mistral ၏ အခမဲ့အစီအစဉ်သည် organization တစ်ခုလျှင် တစ်လ 1B ပမာဏရှိသည့် allowance တစ်ခုဖြစ်သည်။ ၎င်းကို model ငါးခုအောက်တွင် စာရင်းပြုစုထားခြင်းက 5B ဖြစ်လာစေမည်မဟုတ်ပါ။ Model အလိုက် ပေါင်းလျှင် ကျွန်ုပ်တို့၏ ကိုယ်ပိုင် catalog သည် **~7.4B** ဟု ဖော်ပြမည်ဖြစ်သည် (2026-09-03 တွင် ပြန်လည်တွက်ချက်ထားသည်၊ ဤကိန်းဂဏန်းကို CI ဖြင့် စစ်ဆေးထိန်းချုပ်ထားခြင်း မရှိပါ — catalog ပြောင်းလဲသည့်အခါတိုင်း ပြန်လည်တိုင်းတာပါ) — headline တွင် **~1.47B** ဟု ဖော်ပြရခြင်းမှာ provider တစ်ခုစီ၏ account တစ်ခုစီက အမှန်တကယ် သုံးစွဲနိုင်သည့် ပမာဏဖြစ်သောကြောင့် ဖြစ်သည်။
- **နေ့စဉ် cap များကို ပြောင်းလဲတွက်ချက်သော်လည်း rate များကို မပြောင်းလဲတွက်ချက်ပါ။** စာရွက်စာတမ်းတွင် ဖော်ပြထားသော tokens/day cap ကို `× 30` အဖြစ် ပြောင်းလဲသည်။ စာရွက်စာတမ်းတွင် ဖော်ပြထားသော requests/day cap ကို `RPD × ~800 tokens × 30` အဖြစ် ပြောင်းလဲသည်။ requests-per-minute ကိုသာ ထုတ်ပြန်ထားသော provider တွင် လစဉ်ကိန်းဂဏန်း **မရှိပါ**၊ ထို့ကြောင့် _uncapped_ အဖြစ် စာရင်းပြုစုပြီး မည်သည့်အခါမျှ ပေါင်းထည့်ခြင်းမပြုပါ။ Rate limit ကို 24/7 ဖြင့် မြှောက်ခြင်းသည် ကျွန်ုပ်တို့ လက်မခံသော ကိန်းဂဏန်းဖောင်းပွမှု ဖြစ်သည်။
- **ဒေသအလိုက် identity check လုပ်ပြီးမှ ရရှိနိုင်သော quota များကို သီးခြားဖော်ပြထားပါသည်** (`+~6M behind regional identity verification`)၊ အကြောင်းမှာ စာဖတ်သူအများစုက ၎င်းတို့ကို အသုံးမပြုနိုင်သောကြောင့် ဖြစ်သည်။
- **Signup credit များသည် ပထမလအတွက်သာ ဖြစ်ပြီး** ဒုတိယကိန်းဂဏန်းအဖြစ် ဖော်ပြထားကာ ပုံမှန်ရရှိသည့် ကိန်းဂဏန်းနှင့် မည်သည့်အခါမျှ ရောနှောထားခြင်းမရှိပါ။
- **ဤကိန်းဂဏန်းကို CI ဖြင့် စစ်ဆေးထိန်းချုပ်ထားပါသည်။** `npm run check:docs-counts` သည် catalog မှ စုစုပေါင်းများကို ပြန်လည်တွက်ချက်ပြီး ဤဖိုင်၊ README သို့မဟုတ် budget card ရှိ ကိန်းဂဏန်းများနှင့် ကွာဟလာသည့်အခါ build ကို မအောင်မြင်စေပါသည်။

## ToS သတိပြုရန် ဇယား

> **ToS flag သည် အကြံပြုသတိပေးချက်သာဖြစ်ပြီး routing gate မဟုတ်ပါ။** `tos` ဟု အမှတ်အသားပြုထားသော provider များကို default အနေဖြင့် routing နှင့် combo/fallback တို့တွင် ဆက်လက်ထည့်သွင်းထားပါသည်။ Flag ကို `/dashboard/free-tiers` နှင့် `/api/free-tier/summary` တို့တွင်သာ ဖော်ပြပါသည်။ `excludeTosAvoid` query parameter သည် summary view ကိုသာ သက်ရောက်ပြီး global routing ကို မသက်ရောက်ပါ။ ဆုံးဖြတ်ချက်ကို `open-sse/config/freeTierCatalog.ts` တွင် ထားရှိသည် (သတင်းအချက်အလက်ပေးရန်သာဖြစ်ပြီး routing engine များက ဖတ်ရှုခြင်းမရှိပါ)။

> Self-hosted၊ single-user personal proxy အတွက် provider တစ်ခုစီ၏ စည်းမျဉ်းများကို အမြန်ဖတ်ရှုသုံးသပ်ထားခြင်း ဖြစ်သည်။ `caution` = စစ်ဆေးသင့်သော personal-use သို့မဟုတ် proxy ဆိုင်ရာ စည်းကမ်းချက်၊ `ambiguous` = မရှင်းလင်း၊ `ok` = အတိအလင်း ခွင့်ပြုထားသည်။ သတင်းအချက်အလက်ပေးရန်သာဖြစ်ပြီး ဥပဒေအကြံဉာဏ်မဟုတ်ပါ — သင်ကိုယ်တိုင် ဆုံးဖြတ်ပါ။

### ⚠️ သတိပြုရန် — စစ်ဆေးသင့်သော personal-use / proxy ဆိုင်ရာ စည်းကမ်းချက်များ (16)
